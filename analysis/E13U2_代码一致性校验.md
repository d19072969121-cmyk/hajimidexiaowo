## 四、`DeepStudentLogo` 尺寸自洽性 —— ❌ 发现实质缺陷

### 4.1 问题

`src/components/ui/DeepStudentLogo.tsx` 中：

```jsx
<svg viewBox="0 0 409 147" ...>          {/* 宽高比 = 2.7823 */}
  <image href="/ai-study-logo-832.png"
         x="0" y="0" width="409" height="147"
         preserveAspectRatio="xMidYMid meet" ... />   {/* 资源真实比例 = 1.7931 */}
```

**`viewBox` 宽高比（2.7823）与资源真实宽高比（1.7931）不匹配。**

实测资源比例：

| 文件 | 尺寸 | 比例 |
| --- | --- | --- |
| `/root/workspace/analysis/e13_assets/app_logo.png`（源图） | 1664x928 | 1.7931 |
| `public/ai-study-logo-832.png`（资源） | 832x464 | 1.7931 |

`409x147` 这个 viewBox 是**沿用旧内联 SVG wordmark 的**（原 wordmark 是超宽横条 409:147）。换成位图后未随之调整。

### 4.2 后果（已量化）

`preserveAspectRatio="xMidYMid meet"` 的含义是：在 409x147 框内**等比适配、不拉伸**。因资源比框"更方"，实际会**按高度贴合、宽度收缩**：

```
meet 缩放:  min(409/832, 147/464) = 0.31681
实际绘制:  832*0.31681 x 464*0.31681 = 263.6 x 147.0
两侧留白:  各 (409-263.6)/2 = 72.7 px   ->  占 viewBox 宽度 17.8%
```

**显示层换算** —— 组件以 `w-44`（176 CSS px）显示，`:146` 处：

| 指标 | 应有 | 实际 |
| --- | --- | --- |
| 图片显示宽度 | 176 px | **113.4 px（仅 64.4%）** |
| 左右留白 | 0 | **各 31.3 px** |
| 框高度 | — | 176/2.7823 = 63.3 px |

**也就是说：logo 会明显偏小、左右各空出约 31px。** 这是渲染期必然发生的副作用，与是否识图无关 —— 纯几何推算。

> ⚠️ 诚实标注：**我无法用肉眼确认它"看起来"多难看**（不能截屏/识图）。但上述数值来自确定的 SVG 布局规则，不是主观判断。

### 4.3 修复方案（最小改动，2 行）

把 `viewBox` 与 `<image>` 的尺寸改为**与资源同比例**，`meet` 即满框绘制：

```jsx
<svg viewBox="0 0 263.6 147" ...>
  ...
  <clipPath id={clipId}>
    <rect x="0" y="0" width="263.6" height="147" rx="14" />
  </clipPath>
  <rect x="0" y="0" width="263.6" height="147" rx="14"
        className="fill-background stroke-foreground/15" strokeWidth="1" />
  <image href="/ai-study-logo-832.png"
         x="0" y="0" width="263.6" height="147"
         preserveAspectRatio="xMidYMid meet" clipPath={`url(#${clipId})`} />
</svg>
```

验算：`263.6/147 = 1.7931` = 资源比例 → `meet` 下满框无留白；显示宽仍 176px，高 98.2px（比现在的 63.3px 高，因为不再被压扁留白）。

**影响面**：
- 仅 `src/components/ui/DeepStudentLogo.tsx` 一个文件、4 处数值（viewBox + clipPath rect + 底板 rect + image），**不动** `AboutTab.tsx`；
- 源码契约测试 `DeepStudentLogo.source.test.ts` 断言的是 `viewBox="0 0 409 147"` —— **改 viewBox 会让这条断言失败**，需同步更新该断言（这是我上次为通过测试而沿用旧 viewBox 的直接后果，属我的设计失误）。

### 4.4 若不修复会怎样

不会崩溃、不会报错、测试也全绿 —— **这是一个"静默的视觉缺陷"**：纯几何比例问题，任何类型检查/单元测试都发现不了。
