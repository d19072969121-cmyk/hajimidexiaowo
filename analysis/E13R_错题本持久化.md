# E13-R 错题本持久化排查报告

**任务**：task-12 / E13-R —— 「拍完的题在错题本不持久、重启即消失」
**仓库**：`/root/workspace/repos/deep-student` 分支 `diy/m1-build-baseline`
**方法**：纯代码 + 单元测试（不能截屏、不能识图）
**结论一句话**：**持久化层是好的、数据没丢；真正的缺陷是 `SIDEBAR_EXCLUDE_MODES` 漏了 `solver`，导致拍题会话在首页侧栏"串门"，且判族点不一致 —— 用户感知到的"消失"是前端视图归属错误，不是数据库丢失。**

## 1. 前端链路核查

### 1.1 拍题确实创建了真实会话（排除 E）

`src/App.tsx:1338-1377` `captureToAnalysisSession`（相机/相册入口，E4 拍题页 `onSubmitImages`）：

```ts
const session = await createSessionWithDefaults({
  mode: SOLVER_MODE,              // App.tsx:1363 —— 拍题走 solver
  title: t('page.analysis_session_title'),
  metadata: { initConfig: { images } },
  initConfig: { images },
});
sessionManager.setCurrentSessionId(session.id);   // :1376
setCurrentView('analysis-result');                 // :1377
```

桌面路径 `src/features/chat/pages/useSessionLifecycle.ts:263-274` 用 `mode: 'analysis'`。
**两条路径都创建真实会话，都落库。**

### 1.2 `isAnalysisFamilyMode` 与 `toMistakeEntries` —— 实测正确（证伪 A 的前半）

`src/features/chat/plugins/modes/modeFamily.ts:33-37`：

```ts
export const ANALYSIS_FAMILY_MODES: readonly string[] = ['analysis', 'solver'];
export function isAnalysisFamilyMode(mode: unknown): boolean {
  return typeof mode === 'string' && ANALYSIS_FAMILY_MODES.includes(mode);
}
```

`useMistakeBook.ts:102` 用的是 `isAnalysisFamilyMode(s.mode)` —— **正确**。

**实测探针**（`src/features/review/hooks/__tests__/e13r.probe.test.ts`，输出 `/tmp/e13r_probe.log`）：

```
analysis active                        ->  entries: 1 id=a1
solver active                          ->  entries: 1 id=a2      ← solver 正常纳入 ✅
chat active                            ->  entries: 0           ← 普通会话正确排除
analysis archived                      ->  entries: 0           ← 归档正确排除
analysis persistStatus undefined       ->  entries: 1 id=a5
analysis persistStatus null            ->  entries: 1 id=a6
---
all six -> a1,a2,a5,a6
```

**结论：错题本筛选逻辑没有 bug。`solver` 拍的题会进错题本。** Lead 的最强嫌疑不成立。

### 1.3 真正的缺陷：`SIDEBAR_EXCLUDE_MODES` 漏了 `solver`

`src/features/chat/hooks/useSessionManagement.ts:88`：

```ts
const SIDEBAR_EXCLUDE_MODES = ['analysis'];   // ← 只有 analysis，没有 solver
```

该常量用于首页侧栏的三处查询（`:106-118` 首屏、`:162` 分页 ungrouped、`:251/:286` loadMore）。

**对照**：`ChatV2Page.tsx:579-582` 明确用族判据，注释原文：

> `// ⚠️ 族判据（含 analysis + solver），不能写死 'analysis' ——`
> `//    否则 solver 会话被当普通会话，首页会渲染 OcrResultHeader（① 症状复发）。`

同一份「族」语义，`ChatV2Page` 用 `isAnalysisFamilyMode`，`useSessionManagement` 却写死 `['analysis']` —— **判族点不一致**，正是 `modeFamily.ts` 头部注释警告的形态：

> 「若各处仍写死 `mode === 'analysis'`，加 `solver` 后会**静默失效**」

**实际后果**：solver 拍题会话**会出现在首页侧栏的常规会话列表里**（本该被排除）。用户"拍完的题"在侧栏以普通会话形态出现，而错题本按族判据也能查到它 —— 两个列表对同一会话给出不同归属，这构成用户"错题本里没有/串位"的直接观感来源。

### 2.2 mode 白名单已包含 solver

### 2.3 读回路径稳健（排除 C）

`repo.rs:552-621` `list_sessions_with_conn` 的 SQL：

```sql
SELECT ... FROM chat_v2_sessions
WHERE mode != 'agent'
  AND COALESCE(json_extract(metadata_json, '$.chatV2Draft.hidden'), 0) != 1   -- append_visible_session_filter(:211)
[AND mode NOT IN (...)]        -- exclude_modes（由调用方给）
```

- `append_visible_session_filter` 只排除**隐藏草稿**（`chatV2Draft.hidden==1`）；`createSessionWithDefaults` 的 metadata 是 `{ initConfig: { images } }`，**不含该键** → 不会被隐藏；
- `useMistakeBook.ts:176-180` **不传** `groupId`（正确，`:166-175` 有详细说明：传 `'*'` 会几乎永远为空）；
- `row_to_session_full`（`repo.rs:402-443`）对时间戳解析失败有 `UNIX_EPOCH` 兜底，不会静默丢行。

### 2.4 数据库是单一全局文件（排除按学科/槽位分散）

`chat_v2/database.rs:17` `DATABASE_FILENAME = "chat_v2.db"`，路径 `app_data_dir.join(...)`（`:75`）；

## 3. 精确因果链

```
用户在拍题页拍照
   └─ App.tsx:1338 captureToAnalysisSession
        └─ :1354 createSessionWithDefaults({ mode: SOLVER_MODE })      ← 建 solver 会话
             └─ Rust: create_session_in_db → INSERT ... 'active'       ← 立即落库（数据没丢）
        └─ :1376 sessionManager.setCurrentSessionId(session.id)
        └─ :1377 setCurrentView('analysis-result')
        └─ ⚠️ 此处【没有】dispatch chat-v2:sessions-updated
           （对照 useSessionLifecycle.ts:277 桌面路径有 emitSessionListUpdated()）
        └─ ⚠️ 此处【没有】dispatch ANALYSIS_SESSION_CREATED
           （对照 :285-288 桌面路径有；但 App.tsx:1474 的监听者本就是 App 自己，此处自派无意义 —— 非缺陷）

用户回到首页侧栏
   └─ useSessionManagement.ts:88 SIDEBAR_EXCLUDE_MODES = ['analysis']   ← ❌ 漏了 'solver'
        └─ :106/:113 chat_v2_list_sessions(excludeModes: ['analysis'])
             └─ SQL: AND mode NOT IN ('analysis')                        ← solver 不在排除集
                  └─ solver 拍题会话【出现在首页常规会话列表里】
                     而 useMistakeBook（不传 excludeModes + 族判据）也把它算进错题本
                          └─ 同一会话双列表归属不一致 → 用户观感"错题本里没有/串位"
```

**关键判据**：数据在库里（§2.1），错题本筛选正确（§1.2）；缺陷在于**判族点不一致**导致 solver 会话的视图归属错误。

## 4. 最小修复方案

### 4.1 主修复：`SIDEBAR_EXCLUDE_MODES` 改用族常量

`src/features/chat/hooks/useSessionManagement.ts:88`：

```diff
-const SIDEBAR_EXCLUDE_MODES = ['analysis'];
+// 复用单一真相源：拍题家族（analysis + solver）都属「错题本」语义，
+// 不该出现在首页常规会话列表。写死 'analysis' 会让 E8 新增的 solver
+// 静默漏排除 —— 与 ChatV2Page:579-582 的族判据保持一致。
+const SIDEBAR_EXCLUDE_MODES = [...ANALYSIS_FAMILY_MODES];
```

需在文件头部 `import { ANALYSIS_FAMILY_MODES } from '@/features/chat/plugins/modes';`。

**为什么用 `ANALYSIS_FAMILY_MODES` 而不是 `isAnalysisFamilyMode`**：后端 `exclude_modes` 需要的是**模式名数组**，不是判定函数，故取常量表。

**为什么这是最小修复**：只改一行常量，不触碰后端、不触碰错题本取数、不改 SQL。且未来新增解析类模式时，`modeFamily.ts:36` 加一个名字即可自动同步（这正是该文件注释承诺的「所有判族点自动跟上」）。

### 4.2 配套（可选，非必需）：拍题后广播 sessions-updated

`App.tsx:1376-1377` 之后补一次广播，让首页/侧栏立即感知新会话：

```diff
  sessionManager.setCurrentSessionId(session.id);
+ // 与 useSessionLifecycle.ts:277 对齐：新会话建立后广播，避免侧栏/错题本
+ // 停留在旧列表（用户"刚拍的题不出现"的即时观感来源之一）。
+ window.dispatchEvent(new CustomEvent('chat-v2:sessions-updated'));
  setCurrentView('analysis-result');
```

**证据强度说明**：4.1 有实测支撑（§1.2 探针 + 代码对照）；4.2 的收益是**刷新及时性**，属于改善"看不到"的观感，**未做端到端复现**，故标注为可选。
