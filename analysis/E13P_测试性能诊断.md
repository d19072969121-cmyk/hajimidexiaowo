### 关键配置修正（源码级证据）
背景线索称"非 CI 默认按 CPU 核数（8）起 fork"——**实测源码修正为 7**：
`node_modules/vitest/dist/chunks/coverage.DfSpMS-b.js:2974-2976`
`getDefaultThreadsCount = watch ? max(floor(numCpus/2),1) : max(numCpus-1,1)`；
`npx vitest run` 为 run 模式（watch=false）→ **默认 maxForks = 8-1 = 7**。
因此组1 的"默认"实为 7 fork，每 fork 堆上限 4096MB（vitest.config.ts:28-29）。

### 测量期间的固定干扰（如实声明）
测量全程同机存在另一工程师的验证跑（`maxForks=1`，输出 `/tmp/vitest_p2_*.log`）：
主进程 ~230-290MB + 1 个 worker ~110-210MB，期间先后出现 19574 链与 18230 链两批。
其占用 ~2 核 + ~0.35-0.5GB 内存。**三组受同等干扰，组间比值方向可信，绝对吞吐偏悲观**。
（诊断纪律：不杀他人进程，仅在清理本方孤儿时用"跑前 PID 差集"避免误伤。）

## 2. 方法论

- 统一脚本 `/tmp/e13p_measure.sh`：跑前记录 free 基线；跑时 0.5s 采样 `free -m` + 全部 node 进程 RSS 总和；`timeout 100` 兜底；跑后按跑前 PID 差集清理本方孤儿 worker。
- 先跑一次预热（maxForks=1，截断于 100s）对齐三组缓存状态；实测缓存效应小：冷缓存 59 用例/100s → 热缓存 67 用例/100s（+13.6%）。
- 另跑一个单文件 probe（`modelFamily.test.ts`，默认配置）获取**完整跑完的官方 Duration 拆解**。

## 3. 三组实测结果（全部截断于 100s，rc=124，无官方 Duration）

| 组 | 配置 | 100s 出结果用例 | 吞吐(用例/s) | 相对组3 | node RSS 峰值* | MemAvailable 最低 | swap used 变化 |
|---|---|---|---|---|---|---|---|
| 组1 | 默认（7 fork） | **357**（355· + 2x） | 3.57 | 5.3x | 1831MB | **2798MB** | 6004→**6796MB（+792）** |
| 组2 | maxForks=2 | 126 | 1.26 | 1.9x | 1089MB | 2871MB | 6269→6269（±0） |

\* node RSS 为全机 node 进程总和，含同机验证跑 ~0.3-0.4GB；本方净增约为：组1 ≈1.4-1.5GB、组2 ≈0.7GB、组3 ≈0.6-0.7GB。

补充实测细节：

- 组1 内存时序（采样 0.5s，摘 10s 粒度）：起跑 swap=6004 → **16 秒后 swap=6672（+668MB）**；nodeRSS 起跑 302MB → 15s 冲到 1515MB → 峰值 1831MB。7 fork 同时冷启动把可用内存瞬间抽干并写入 swap，是"内存压力"最直接的证据。
- 组2/组3 全程 swap 平稳甚至回落（换出页被回读释放），工作集稳定。
- 组1 中 2 个 `x` = 失败用例（dot reporter 源码 `fail={char:"x"}`，index.VByaPkjc.js:1263-1266）；因截断未到汇总阶段，**失败详情未证实**。

## 4. 耗时构成分析（单文件 probe，唯一跑完的官方 Duration）

`modelFamily.test.ts`（81 用例，纯 ts）默认配置完整跑完：

```
Duration  10.94s (transform 308ms, setup 2.91s, collect 141ms,
          tests 41ms, environment 5.39s, prepare 837ms)
```

| 阶段 | 耗时 | 占比 |
|---|---|---|
| environment（jsdom 装载） | 5.39s | 49.3% |
| setup（vitest.setup.ts，每文件执行） | 2.91s | 26.6% |
| prepare | 837ms | 7.7% |
| transform | 308ms | 2.8% |
| collect | 141ms | 1.3% |
| **tests（断言本身）** | **41ms** | **0.4%** |

结论：**单文件端到端 ~11s 里，断言只占 0.4%，环境初始化（environment+setup+prepare）占 ~84%**。
forks 池默认 isolate，每个测试文件都要重付一遍该成本 → 总耗时 ≈ 文件数 × 初始化成本，fork 只能并行摊薄、无法消除。
注意 probe 是纯 ts 文件（tests 41ms）；47 个文件中 tsx 组件测试的 tests 段（渲染 + userEvent）为秒级，单文件成本更高——组3 实测 100s 仅出 67 用例（约 5-9 个文件的量）与此吻合。

## 5. 瓶颈判定

1. **第一瓶颈（结构性，与 fork 数无关）：每文件环境初始化 × 文件数。**
   jsdom 装载 5.4s + setup 2.9s 每文件重付。1 fork 串行全子集估算 ≈ 47 文件 × 10-20s ≈ **10-15 分钟**（估算，见 §7）；组3 实测吞吐 0.67 用例/s 与此一致。
2. **第二瓶颈（组1 特有）：默认 7 fork 触及本机内存崩溃边界。**
   前 16s swap +668MB、MemAvailable 压到 2798MB、本方 RSS 净增 ~1.5GB；背景已实测 MemAvailable 3.1GB 时发生 `node::TearDownOncePerProcess` Aborted——7 fork 默认配置在本机就是在崩溃水位附近运行。
3. **CPU 抢占是三阶因素。**
   2 fork 吞吐 1.9x（近线性）证明 8 核并未饱和；7 fork 吞吐衰减到 5.3x（<7x）的原因是内存压力 + 同机验证跑占核，而非 CPU 数量不足。
4. 换页颠簸（GC 触发换页回读）：**未证实**（/proc/vmstat 不可读），仅有 swap 快速增长这一间接证据。

## 6. 可落地建议（含风险）

1. **立即可用：本机跑测试加 `--poolOptions.forks.maxForks=2`。**
   收益：吞吐 1.9x 于串行、swap 零增长、内存安全边际大。风险：极低。
2. **配置固化：vitest.config.ts 非 CI 分支显式 `maxForks: 2`**（与 CI 分支一致，消灭"默认 7 fork"这个隐性炸弹）。
   风险：本机全量跑从"理论更快但崩溃边缘"换成"稳定但变慢"；需要更快的机器可用环境变量 `VITEST_MAX_FORKS` 覆盖（源码 cac.BfaZ95xE.js:3745 支持），不必改配置。
3. **治本方向 A：纯逻辑测试免 jsdom。** 对纯 ts 测试文件加文件级注释 `// @vitest-environment node`，每文件立省 ~5.4s jsdom 装载（probe 实证 modelFamily.test.ts 是纯 ts 却付了全额 jsdom）。
   风险：需逐文件核对 DOM 依赖；改错立刻报 `document is not defined`（显性失败，易回滚）。
4. **治本方向 B：治理 vitest.setup.ts（每文件 2.91s）。** 审计 setupFiles 是否全量引入重库，按需拆分/懒加载。
   风险：中，需回归验证 setup 副作用。
5. **治本方向 C：归拢小文件。** 初始化按文件计费，把同一域的多个小测试文件合并为 describe 组可线性省时间。
   风险：测试组织变更，需团队评审。
6. **不建议**：singleFork（vitest.config.ts:19-20 已记录 GC 抖动近似死锁教训）；isolate:false（jsdom 内存跨文件累积，正是配置注释里规避过的老坑）。

## 7. 证据强度自评

**强（实测/源码）**：三组吞吐与内存/swap 全套数字（0.5s 采样）；probe 官方 Duration 拆解；默认 7 fork（coverage.DfSpMS-b.js:2974-2976）与 `x`=fail（index.VByaPkjc.js:1263-1266）源码证据。

**中（带干扰的实测）**：三组绝对吞吐受同机验证跑干扰（同等叠加，比值方向可信；绝对值偏悲观，幅度未量化）。

**弱/未证实（如实标注）**：
- 跑完整个子集的真实总 Duration：三组均截断于 100s，未取得（1 fork 全子集 10-15 分钟、2 fork 约 5-8 分钟均为基于文件数 × 单文件初始化成本的**估算**，非实测）；
- 全子集总用例数：`vitest list` 两次 100s 超时零输出，**未证实**；
- 换页颠簸：/proc/vmstat 沙箱不可读，**未证实**；
- 组1 的 2 个失败用例详情：截断丢失，**未证实**；
- cgroup 限额：沿用背景"无"，未独立复核。
