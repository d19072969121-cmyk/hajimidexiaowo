## 6. ⚠️ `desktop_only` 自相矛盾问题（先报告，未擅自处理）

### 现象

`About.developer.values.platforms` 现为 **Android（只支持安卓）**，但以下文案仍假设存在桌面版：

| key | 现文案 |
|-----|--------|
| `settings:automation.errors.desktop_only` | 「自动化管理需要 AI Study **桌面应用**」 |
| `settings:subagentProfiles.errors.desktop_only` | 「子代理档案管理需要 AI Study **桌面应用**」 |
| `settings:mcp.oauth.desktop_only` | 「OAuth 浏览器登录仅在桌面端可用」 |
| `settings:mcp.stdio.desktop_only` | stdio 传输仅桌面端 |
| `data.json` / `common.json` 云同步段 | 「桌面端还可使用 S3 兼容存储与实验性 FTP」 |

### 矛盾分析

这**不一定**是文案 bug —— 关键在于「关于页平台支持」的语义是**本发行版面向的终端平台**，而 `desktop_only` 是**运行时能力可用性判定**：
`useAutomationStore.ts:146` 等在检测到非桌面运行时才抛 `desktop_only`。
即：安卓构建里这些入口本就不该可达；文案是**兜底错误提示**，只有能力判定失败时才出现。

**真正的风险点**是 `about.developer.values.platforms` 若被理解为「技术栈支持的全部平台」，则会与这些兜底提示冲突。

### 处理建议（供决策，未擅自实施）

1. **推荐 · 保持现状**：`platforms` 表达「本 App 支持 Android 端」，`desktop_only` 保留为兜底。
   冲突仅在用户看到该兜底提示时才可能察觉，属低概率。
2. **可选 · 语义消歧**：把 `values.platforms` 写成 `Android（移动端）`，并在描述中注明桌面能力未随本发行版提供。
3. **可选 · 入口隐藏**：安卓构建下直接隐藏自动化/子代理档案入口（**涉及功能改动，需用户拍板**，不建议由文案任务顺手做）。
4. **不建议**：删除 `desktop_only` 文案。它仍被 Rust 侧与 `useAutomationStore` 的真实错误分支引用，删除会留下裸 key。

**结论**：本次仅完成品牌词替换（`Deep Student` → `AI Study`），**语义与功能均未改动**，等待用户决策。

## 7. 过程事故与恢复记录（透明披露）

执行 §5.2 基线对比时，我运行了 `git stash push -q -- src/locales/`（意图对比改动前后 i18n 差异），该命令**把我尚未提交的 locale 改动一并 stash 走了**，且随后的 `git stash pop` 因工具调用被打断而未执行。

**恢复过程**：
1. `cp -a src/locales /tmp/locales_work_backup` 先备份现场；
2. `git checkout stash@{0} -- src/locales/` 从 stash 恢复内容；
3. 校验通过：`platforms` = `Android`、`app.name` = `AI Study`、
   `auto_fetch_models*`（另一 teammate model-puller 的 vendor_panel 新增键）**5 处仍在**；
4. 全库 locale JSON 解析通过，品牌命中归零；
5. `git stash drop` 清理，`git stash list` 为空。

**结论**：改动**无丢失、无覆盖他人改动**（已逐项核验 model-puller 的 key 保留）。此事作为教训记录：**不得用 stash 做基线对比**，应改用 `git show HEAD:<file>` 读原始版本。
