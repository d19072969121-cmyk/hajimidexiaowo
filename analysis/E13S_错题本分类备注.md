## 2. merge 陷阱（重要设计约束）

后端 `merge_session_metadata`（`src-tauri/src/chat_v2/handlers/manage_session.rs:1162-1171`）语义是：

```rust
match incoming_metadata {
    Some(Some(metadata)) => Some(metadata.clone()),   // 整块替换，非深合并
    Some(None) => None,
    None => existing_metadata,
}
```

**整块替换、非深合并**——`Some(Some(v))` 直接 `clone` 覆盖整个 metadata 块。

因此 `buildNoteMetadata`（`useMistakeNote.ts:60`）必须：

1. 先 `{ ...existingMetadata }` 展开**全部**既有键；
2. 只改 `mistakeNote` 一个键；
3. 整体回写。

否则会把 `availableSkillsSnapshot`、`chatV2Draft` 等兄弟键**一并抹掉**。已正确实现（`useMistakeNote.ts:65-66` 的展开逻辑 + `isNoteChanged` 的只读比较），并有测试锁定该行为。**后续任何往 `metadata` 写新键的功能都必须复用同一模式，禁止直接传单键对象。**

## 3. 已知限制（一）：时间过滤取数口径不同（如实声明）

- 后端取数 SQL：`ORDER BY updated_at DESC LIMIT ? OFFSET ?`（`src-tauri/src/chat_v2/repo.rs:621`，调用方传 LIMIT 500）。
- 前端时间过滤：按 `createdAt`。

两个口径不同 → **analysis 会话超过 500 条时，「拍得早且久未动」的题可能被挤出 500 条窗口**，「本月 / all」两个档位不受影响。

该边界已写入 `mistakeTimeFilter.ts` 尾注释 + 2 个锁边界测试。将来根治方案：给 `chat_v2_list_sessions` 加 `createdAfter`/`createdBefore` 参数下推到 SQL（`AND created_at >= ?`），本模块保留 `filterByTimeRange` 作 UI 侧兜底——详见尾注释，本次不引入后端改动。

## 4. 已知限制（二）：fail-close 可发现性（如实声明）

全库**无**任何 `#[tauri::command]` 能读 `StartupComponentHealthState`。chat_v2 State 未注册时（启动期 fail-close 阻断，见 E13R2），Tauri 只回**通用错误**——前端**无法区分**「被阻断（不可自愈）」与「临时失败」两种情形。

故错误条按钮文案使用条件句：「若反复失败，去设置检查数据状态」，**不断言**「你被阻断了」。真要区分需新增 Rust 查询命令（超本任务范围，已在代码备注）。这决定了错误条只做「可发现」，不做「可诊断」。
